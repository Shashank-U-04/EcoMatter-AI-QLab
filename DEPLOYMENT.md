# Deployment Guide

No Docker required — Render builds the backend on its servers from
`render.yaml`, and Vercel builds the frontend. Both free tiers.

## Architecture

| Piece      | Host   | Config                                  |
|------------|--------|-----------------------------------------|
| FastAPI backend | Render (free web service) | `render.yaml` (repo root) |
| PostgreSQL | Render (free database)     | provisioned by `render.yaml` |
| Next.js frontend | Vercel (free)        | dashboard settings below |

## 1. Backend + database (Render)

1. Sign up at https://render.com with your GitHub account and authorize
   access to this repo.
2. Dashboard → **New → Blueprint** → select `EcoMatter-AI-QLab`.
   Render reads `render.yaml` and creates the `ecomatter-api` web service
   and the `ecomatter-db` PostgreSQL database.
3. Click **Apply**. First build takes ~5–10 minutes (installs RDKit etc.).
4. Note the service URL, e.g. `https://ecomatter-api.onrender.com`.
   Check `https://<service-url>/health` returns `{"status": "ok"}`.

`JWT_SECRET` is auto-generated by Render; `DATABASE_URL` is wired to the
database automatically. Nothing to paste by hand except CORS (step 3).

## 2. Frontend (Vercel)

1. Sign up at https://vercel.com/signup with GitHub.
2. **Add New → Project** → import `EcoMatter-AI-QLab`.
3. On the configure screen:
   - **Root Directory**: `frontend`
   - Framework preset: Next.js (auto-detected)
   - **Environment variable**: `NEXT_PUBLIC_API_URL` = the Render URL
     from step 1 (no trailing slash)
4. Deploy. Note the URL, e.g. `https://ecomatter-ai-qlab.vercel.app`.

## 3. Connect the two (CORS)

In Render → `ecomatter-api` → **Environment**, set:

```
CORS_ORIGINS=https://<your-vercel-url>
```

Comma-separate to allow several origins. Save; Render redeploys.

## 4. Firebase login (optional)

Firebase manages signup/login (email/password + Google) and sends
password-reset emails. Without it, the app uses its built-in auth.

1. https://console.firebase.google.com → create a project (Analytics off).
2. Build → Authentication → Get started → enable **Email/Password** and
   **Google** providers.
3. Authentication → Settings → Authorized domains → add the Vercel domain.
4. Project settings → Your apps → add a **Web** app → copy the config.
5. Vercel → Project → Settings → Environment Variables, add (from config):
   `NEXT_PUBLIC_FIREBASE_API_KEY`, `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN`,
   `NEXT_PUBLIC_FIREBASE_PROJECT_ID`, `NEXT_PUBLIC_FIREBASE_APP_ID` — then
   redeploy.
6. Render → `ecomatter-api` → Environment, add `FIREBASE_PROJECT_ID` with the
   same project ID. No service-account secret is needed: the backend verifies
   ID tokens against Google's public keys.

## Free-tier notes

- The Render service **sleeps after 15 min idle**; the first request after
  that takes ~50s to wake. Fine for a demo, worth mentioning in one.
- Free Postgres has a 1 GB cap and (per Render policy) expires after a
  period on the free plan — check the dashboard banner for the date.
- `backend/storage/` (generated reports) is ephemeral on Render; reports
  are regenerated on demand, so nothing is lost.
- GA runs use `GA_TIME_BUDGET_SECONDS=90`; free-tier CPUs are slower than
  a dev machine, so runs return fewer generations in that budget.

## Local development (unchanged)

SQLite remains the default locally — no Postgres or Docker needed:

```
cd backend && uvicorn app.main:app --reload
cd frontend && npm run dev
```
